WHY THIS APPROACH

LPは、情報を足すより
迷いを減らすことから。

サービスの強みが伝わらない、スマホで読みづらい、問い合わせまで遠い。そんな課題を、構成・コピー・デザイン・技術の4つの視点から整理します。

◎01 / MESSAGE

伝える順序を設計

サービス説明を並べるだけでなく、悩み・価値・根拠・行動の順に整理します。

▣02 / EXPERIENCE

スマホでも迷わない

文字量、余白、ボタン、FAQを見直し、必要な情報へたどり着きやすくします。

↗03 / IMPROVEMENT

改善の起点を作る

GA4などの計測要件を整理し、公開後の見直しにつながる設計を目指します。

PROJECT FIT

別の仕組みが向くケース。

制作方法は目的で選びます。最初から静的HTMLありきではなく、必要な更新・機能に合わせて判断します。

静的LPを検討しやすい

1つのサービスを、分かりやすく伝えたい

  • 問い合わせ・資料請求など、主な目的が明確
  • 更新頻度が低く、内容を絞った1ページ
  • 表示速度やシンプルな運用を重視
別の構成も比較したい

投稿・予約・決済などが中心になる

  • 頻繁に記事や商品を追加したい
  • 会員機能・予約・決済をサイト内で完結したい
  • 複数担当者による日常的な更新が必要

※フォームや計測機能は外部サービスの利用・追加費用が発生する場合があります。要件を確認して提案します。

WHAT WE DO

制作前の整理から、
公開前の監査まで。

1ページに必要な仕事を6つの工程に分けて、抜け漏れを減らします。

01 / STRATEGY

目的・ターゲット整理

誰に届け、どの行動を成果地点にするかを定義。

02 / COPY

構成・コピー設計

03 / BUILD

04 / MOBILE

05 / SEARCH

06 / QUALITY

監査・ブラッシュアップ

表示崩れ、導線、アクセシビリティ、文章を点検。

RIGHT TOOL, RIGHT HOSTING

GitHubで管理。
公開先は、用途に合わせて。

HTML/CSSはGitHubでバージョン管理しやすい形式で制作します。ただし、GitHub Pagesには主に商取引を促進するサイトを無料ホストする用途への制限があります。商取引を主目的とするLPは、GitHub Pagesでの公開を前提にせず、利用条件に合うホスティングを選定します。

更新頻度が高い、会員機能や複雑なフォームが必要といった案件では、WordPress等のCMSや外部サービスを含めて判断します。

FREQUENTLY ASKED QUESTIONS

よくある質問

公開先や費用、SEOなど、制作前によくある疑問をまとめました。

GitHub Pagesなら商用LPも無料で公開できますか？

GitHub Pagesには、オンラインビジネスや主に商取引を促進するサイトを無料ホスティングする用途への制限があります。コードはGitHubで管理しつつ、商用LPの公開先は利用条件に合うサービスを選びます。

WordPressより静的LPが向いていますか？

更新頻度が低く、シンプルな1ページ構成なら静的LPが向く場合があります。記事投稿、複雑なフォーム、会員機能などが必要な場合はWordPress等も比較します。

SEO対策は含まれますか？

title、description、見出し構造、モバイル対応など基本的なSEOは対象です。検索順位の上昇や成果を保証するものではありません。

保守・軽微更新の契約で何でも修正できますか？

いいえ。想定は文言やリンクなどの軽微な更新です。作業回数・対応時間・対象範囲は正式契約前に確定し、デザイン変更や大幅改修は別途見積となります。

フォームや決済も付けられますか？

必要に応じて外部サービス等との連携を検討できます。個人情報の取り扱い、外部費用、運用方法を確認し、別途見積とする場合があります。

納品後のソースコードやドメインは誰が管理しますか？

ソースコードの利用条件、ドメインや公開先アカウントの名義・管理権限、引き渡し方法を事前に確認します。著作権や権利移転の範囲は正式契約で定めます。

正式な見積で追加料金になるのはどんな場合ですか？

追加ページ、原稿の大幅作成、写真・有料素材、複雑なフォーム・予約・決済、公開設定、継続的な分析・改善などは別途費用となる場合があります。着手前に範囲を提示します。

制作したLPは自動的に公開されますか？

いいえ。基本は制作ファイルの納品までです。本番公開・ドメイン設定・既存ページの上書きは別途見積の対象となり、内容・公開先・作業範囲について明示承認を受けた場合に限り対応します。
